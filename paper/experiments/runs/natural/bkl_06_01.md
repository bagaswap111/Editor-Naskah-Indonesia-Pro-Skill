Setelah membaca subbab ini, Anda akan mampu:

- Membuat dan menggunakan *Tools* (fungsi Python kustom) beserta *function calling* dan dukungan *Model Context Protocol* (MCP).
- Mengamankan *deployment* dengan RBAC multi-pengguna (*multi-user*), *rate limiting*, dan *reverse proxy* HTTPS.

### Dari Terminal ke Antarmuka Bergaya ChatGPT

Bayangkan Anda baru saja mengunduh DeepSeek V4 Flash melalui Ollama. Untuk mengobrol dengannya, pilihan Anda adalah menjalankan perintah `ollama run` di terminal — cepat, tetapi kering: tidak ada riwayat percakapan yang nyaman, tidak ada tempat menyimpan dokumen, dan tidak ada cara bagi model untuk menjalankan kode. Open WebUI hadir untuk mengisi kekosongan itu. Proyek ini adalah *frontend web self-hosted* yang awalnya bernama "Ollama WebUI" dan kemudian berkembang menjadi platform lengkap: pengganti ChatGPT *self-hosted* yang dapat dijalankan di mesin sendiri, sepenuhnya gratis dan *open source* [6].

Yang membuat Open WebUI menarik bukan hanya tampilannya yang mirip layanan komersial, melainkan tiga lapis kemampuannya: antarmuka percakapan yang nyaman, *pipeline* RAG bawaan yang siap pakai, dan sistem *Tools* yang memungkinkan model memanggil fungsi. Kombinasi ini menjadikannya gerbang (*gateway*) yang menghubungkan pengguna, dokumen, dan mesin inferensi dalam satu antarmuka.

### Arsitektur: *Backend* Python, *Frontend* Svelte

Secara arsitektur, Open WebUI terdiri atas dua bagian yang dipisahkan dengan tegas [1]. *Backend* ditulis dalam bahasa Python menggunakan kerangka kerja (*framework*) FastAPI — *backend* ini bertanggung jawab atas autentikasi, *routing* permintaan, orkestrasi RAG, eksekusi *Tools*, dan semua logika sisi peladen (*server*). *Frontend* dibangun dengan Svelte, kerangka kerja JavaScript yang dikenal ringan dan reaktif — *frontend* inilah yang dirender di peramban (*browser*) pengguna. Keduanya berkomunikasi melalui REST API dan WebSocket, sehingga respons model dapat mengalir (*streaming*) token demi token tanpa menunggu seluruh jawaban selesai.

Pemisahan ini memberi konsekuensi praktis yang penting: Open WebUI hanyalah *frontend*, bukan mesin inferensi. Ia tidak menjalankan model sendiri, melainkan berperan sebagai konduktor yang menyalurkan permintaan ke mesin inferensi di belakangnya — seperti orkestra yang menempatkan setiap instrumen ke posisinya masing-masing.

### Dukungan Multi-Engine

Open WebUI mendukung banyak mesin inferensi sekaligus, dan Anda dapat berpindah mesin bahkan di tengah percakapan:

- Ollama — mesin bawaan yang paling mudah; Open WebUI bahkan menyediakan *image* Docker yang sudah membundel Ollama di dalamnya.
- API yang kompatibel dengan OpenAI (*OpenAI-compatible API*) — titik akhir (*endpoint*) apa pun yang mengikuti format API OpenAI, termasuk vLLM, LM Studio, peladen llama.cpp, hingga penyedia awan (*cloud*).
- vLLM — untuk kebutuhan *throughput* tinggi dan *continuous batching* di kelas peladen.

Basis data bawaan Open WebUI adalah SQLite — cukup untuk penggunaan pribadi hingga tim kecil. Untuk skala yang lebih besar, Open WebUI mendukung PostgreSQL sebagai pengganti, yang menangani banyak koneksi bersamaan dengan lebih baik [7].

### Tabel 1: Opsi *Deployment* Open WebUI

Berikut perbandingan metode *deployment* yang tersedia, dari yang paling sederhana hingga skala perusahaan (*enterprise*):

| Metode | Perintah | Dukungan GPU | Cocok Untuk |
|:---|:---|:---:|:---|
| Docker Standalone | `docker run ghcr.io/open-webui/open-webui:main` | Lewat hos (*host*) | Pengguna dengan Ollama terpisah |
| Docker + Ollama | `docker run ghcr.io/open-webui/open-webui:ollama` | `--gpus=all` | Konfigurasi *all-in-one* termudah |
| Docker + CUDA | `docker run ghcr.io/open-webui/open-webui:cuda` | CUDA asli (*native*) | Pengguna GPU NVIDIA |
| Docker Compose | `docker compose up` | Ya | *Deployment* produksi |
| Kubernetes | *Helm chart* / `kubectl` | Ya | Skala perusahaan |
| Native (`pip`) | `pip install open-webui` | Ya | Pengembangan |

   * Menambahkan tanda kutip/format kode pada perintah terminal di dalam paragraf (misalnya `ollama run`) agar lebih rapi secara visual dan mudah dibaca oleh praktisi IT.
